 Usage: `#[auto_assign(field = value,...)]`
 What it does:
 - it assembles small internal macros that build and inject the final state-transitioned struct (according to the declared updates in the attribute list) into the function body at compile-time.
 - These internal macros are exposed at the `#[type_state]` root and are implicitly invoked by the consumer if `#[auto_assign(...)]` is detected.
 - The consumer can now create type state builders with dozens of fields without the repeated & annoying struct construction boilerpalte.
 - This is especially useful for
  1. complex state transition logic where a state has multiple dependencies.
  2. as long as the compiler is unable to handle the `..self` syntax during construction (see: https://github.com/ozgunozerk/state-shift?tab=readme-ov-file#3-self-is-ok-to-use-but-there-is-one-exception)

 This macro is consumed by the `#[impl_state]` macro, and it basically guides `#[impl_state]` macro to:
- construct the return structs of the methods generated by the `#[auto_assign(...)]` macro
 hence, it is empty, because it delegates its job to `#[impl_state]` macro
- the reason for that delegation is: `#[auto_assign(...)]` macro needs the below from the encapsulating `impl` block for the methods
- name of the impl block (name of the struct)
- Furthermore, it relies on `[#type_state]` to generate appropriate helper macros that act as a struct construction factory
- the reason for that dependency is: `#[type_state]` is the only entity that has knowledge of the full struct definition. To make the auto assembly work,  `#[auto_assign(...)]` needs to know the shape of the struct (the fields). This Information is is impossible to access at compile-time with the limited context of `#[impl_state]`. Thus we encode this knowledge in the helper macros and make this information implicitly accessible to `#[auto_assign]`.

Details:
Wiring up several setters is now not as dreadful anymore, because instead of:
```rs
 #[require(RaceSet, B, C, D, E, F, G)]
 #[switch_to(RaceSet, LevelSet, SkillSlotsSet, D, E, F, G)]
 fn set_level(
     self,
     level_modifier: u8,
     init_skill_slots: u8
 ) -> PlayerBuilder {
    let level = match self.race {
        Some(Race::Orc)     => level_modifier + 2,
        Some(Race::Human)   => level_modifier,
        None                => unreachable!("type safety ensures that `race` is initialized"),
    };
    PlayerBuilder {
        race:        self.race,
        level:       Some(level),
        skill_slots: Some(init_skill_slots),
        spell_slots: self.spell_slots,
        health:      self.health,
        strength:    self.name,
        agility:     self.agility,
    }
}
```
 we can now do:

```rs
 #[auto_assign(level = level, skill_slots = init_skill_slots)]
 #[require(RaceSet, B, C, D, E, F, G)]
 #[switch_to(RaceSet, LevelSet, SkillSlotsSet, D, E, F, G)]
 fn set_level(
     self,
     level_modifier: u8,
     init_skill_slots: u8
 ) -> PlayerBuilder {
    let level = match self.race {
        Some(Race::Orc)     => level_modifier + 2,
        Some(Race::Human)   => level_modifier,
        None                => unreachable!("type safety ensures that `race` is initialized"),
    };
    // - Here, PlayerBuilder is compile-time generated based on
    //    `<struct_field_id> = <struct_field_alias>` assignments in #[auto_assign(..)]
    // - The v2 implementation checks if `<struct_field_id>` is defined on the struct
    //    and displays a compile error if not. The macro also checks for duplicate `<struct_field_id>`s
    // - The validity of the `<struct_field_alias>` assignment itself is automatically
    //    checked by the rust compiler after the struct generation step
    // - For a struct field of type Option, the user is allowed to pass `<struct_field_alias>`
    //    a) as an Option type or
    //    b) as an "unwrapped" type,
    //   -> the macro resolves both variants to Option<T>.
    // - Non-Option struct fields (e.g. of type u8 with default value 0) are also supported.
 }
```

#### UX
```rs
#[type_state(states = (Initial, RaceSet, LevelSet, SkillSlotsSet, SpellSlotsSet), slots = (Initial, Initial, Initial))]
struct PlayerBuilder {
  race:        Option<Race>,
  level:       Option<u8>,
  skill_slots: Option<u8>,
  spell_slots: Option<u8>,
}

#[impl_state]
impl PlayerBuilder {
  #[require(Initial, Initial, Initial)] // require the default state for the constructor
  fn new() -> Self {
    PlayerBuilder {
      race:        None,
      level:       None,
      skill_slots: None,
      spell_slots: None,
    }
  }

  #[auto_assign(level = some_level_calc, race = race)]
  #[require(RaceSet, B, C)]
  #[switch_to(RaceSet, LevelSet, C)]
  fn set_level(
    self,
    level_modifier: u8,
    race: Race,
  ) -> PlayerBuilder {
    let some_level_calc = match self.race {
      Some(Race::Orc) => level_modifier + 2,
      Some(Race::Human) => level_modifier,
      None => unreachable!("type safety ensures that `race` is initialized"),
    };
  }
  ```

```rs
macro_rules! default_or_override {
  ($self:expr, $field:ident,  [])
    =>  {$self.$field};
  ($self:expr, race,          [race         = $val:expr $(,$($rest:tt)*)?])

    =>  {OptionWrapper::wrap($val)};
  ($self:expr, spell_slots,   [spell_slots  = $val:expr $(,$($rest:tt)*)?])
    =>  {OptionWrapper::wrap($val)};
  ($self:expr, $field:ident,  [$other:ident = $val:expr, $($rest:tt)*])
    =>  {
      default_or_override!($self, $field, [$($rest)*])
  };
  ($self:expr, $field:ident,  [$other:ident = $val:expr])

      default_or_override!($self, $field, [])
  };
}
```
